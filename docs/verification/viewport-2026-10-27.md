# Native viewport verification, 2026-10-27

The native review harness exercises the application canvas with real OCCT geometry.
It uses corpus feature definitions in `examples/viewport_review/corpus.rs`, separate
from the production feature compiler and solid-creation commands. The normal app
still needs that compiler; these fixtures do not establish the sketch-to-solid
workflow.

## Environment and scenes

- Mac with Apple M5 Max, Metal, debug Rust build, OCCT 7.9.3 and eframe 0.36.2.
- Window: 1360 × 860 logical points, observed at 2720 × 1720 physical pixels.
- 1,000 instances share one 30 × 22 × 12 mm box asset.
- 100 mixed parts use 100 separate assets: boxes, hollow circular extrusions and
  plates with circular holes. Their dimensions and placements are reproducible in
  the corpus source.
- Display deflection: 0.2 mm; kernel numerical policy remains independent.

The harness requests 240 continuously repainted camera frames, then stops its
animation. Inter-frame statistics exclude the first 30 ready frames. Selection
timing measures synthetic CPU queries. It does not measure OS input-to-photon
latency or GPU execution time in isolation.

| Scene | p95 inter-frame interval | p95 UI CPU work | p95 CPU selection query | Mesh/instance payload |
|---|---:|---:|---:|---:|
| 1,000 shared instances | 10.423 ms | 5.198 ms | 2.085 ms | 137,912 bytes |
| 100 mixed parts | 12.217 ms | 3.982 ms | 0.807 ms | 1,477,808 bytes |

Both observed p95 frame intervals are below the initial 16.7 ms target on this
machine. This is a short debug-build baseline, not acceptance on weaker hardware
or a sustained thermal test. The payload counts exclude provenance, allocator,
native B-rep, driver and GPU allocations.

Process RSS samples were approximately 130–137 MiB for the 1,000-instance scene
and 148 MiB for the mixed scene. During a separate quiet 95-second interval,
process 12428's cumulative CPU counter stayed at 4.70 seconds at 0.01-second
resolution; both instantaneous CPU samples read 0.0%. Raw local outputs are in
`artifacts/viewport-review/`, including `idle-process-12428.json`. The harness
overwrites its per-scene source and metric files on subsequent runs; the table
above records the observations from this verification.

## Interactive checks

The native window visibly rendered both scenes. In the mixed scene:

- Tree selection displayed the part name, material and tags.
- Fit selected enlarged the chosen hollow part while retaining its neighbors.
- Direct viewport clicks selected a face, circular B-rep edge and vertex, with
  world coordinates in Inspector. The observed vertex was at 45, 62, 0 mm.
- The visual-style control changed the real scene to B-rep wireframe, without
  triangle diagonals.
- Holding D panned the view while the selected vertex coordinates and document
  revision stayed unchanged.
- The XY grid followed the view rather than remaining around the world origin.

The previous application instance's constrained 100 × 60 mm sketch was saved to
`artifacts/native-constraint-final.multicad.json` before closing that older build.

## Reproduction and remaining work

```sh
cargo run -p multicad-app --example viewport_review --locked --offline
cargo run -p multicad-app --example viewport_review --locked --offline -- --mixed
cargo test -p multicad-app --example viewport_review --locked --offline
```

The harness saves its canonical source fixture and JSON metrics locally. Native
window launch and physical GPU access must be available; no installed application
or Python/Node runtime is required.

Workspace tests cover stale scene publication, retained previous results, failed
and retried backend requests, source identity, occlusion, perspective edge hits,
malformed topology metadata, selected bounds and grid limits. The separate Metal
pixel test covers all four styles and selection highlighting.

CAD-57 remains unfinished: adaptive tessellation, section overlays, remaining
preview integration and complete input-feedback timing still need verification.
Visible reference repair remains CAD-55 work. Windows and Linux runtime behavior
and physical middle-button/right-button navigation were not verified here.
